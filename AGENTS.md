# go-twelvedata

Unofficial Go client for the Twelve Data API, generated from the OpenAPI document Twelve Data publishes. If you only want to use the client from an agent, read [.agents/skills/go-twelvedata/SKILL.md](.agents/skills/go-twelvedata/SKILL.md) instead; this file is about changing the code.

## Architecture

One generated package, `twelvedata`, at the module root, driven by `gen.go`:

`scripts/fetch-spec.sh` downloads `https://api.twelvedata.com/doc/swagger/openapi.json` to `api/openapi.json`. `scripts/patch-spec.sh` writes `api/openapi.patched.json`, converting schema `examples` arrays to a single `example`, declaring OpenAPI 3.0.3 for kin-openapi and removing component-level `x-go-name` overrides. oapi-codegen reads the patched spec with `config.yaml` and writes `client.gen.go`. All 187 paths are generated.

## Stack

- Go 1.26.9.
- oapi-codegen, pinned as a `tool` dependency in `go.mod`.
- Runtime: `github.com/oapi-codegen/runtime`.

## Layout

- `gen.go`, `config.yaml`, `client.gen.go`: the package.
- `client_test.go`, `example_test.go`: tests, including the README example.
- `scripts/`: spec download, the OpenAPI patch, lint and security scan scripts.
- `api/`: the downloaded spec, gitignored.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the spec and regenerate
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- The upstream document is OpenAPI 3.1.0, API version 0.0.1. Its schema `examples` arrays need the patch before generation. Component-level `x-go-name` overrides reuse names such as `Meta` for distinct schemas, so the patch removes those overrides. Property and parameter overrides remain intact. Preserve all operations when updating that patch.
- Without the `number` to `float64` mapping in `config.yaml`, number schemas become `float32`. Many prices, including `GetPrice`'s `Price`, are strings in the spec and remain strings.
- Auth is `Authorization: apikey <key>`. The spec also allows `apikey` in the query string. Tests use a local HTTP server and fake credentials.
- `x-required-group` extensions are not generated validation. Supply an instrument identifier such as `Symbol` for price calls. `GetPriceWithResponse` takes a pointer to `GetPriceParams`.
- Method names follow operation IDs. The batch endpoint is `POST /batch`, generated as `AdvancedWithResponse`. Enum values are prefixed and type naming collisions are resolved in `config.yaml`.
- `make generate` always downloads the current spec, so it can change the client even when nothing here changed. Review the generated diff before committing it.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When the checks fail, Claude edits the repository to fix them, but a fix may not touch the paths listed under `fix_protected_paths` in that workflow: the workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, the lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
